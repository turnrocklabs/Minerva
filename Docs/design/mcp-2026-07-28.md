## 1. Decisions and scope

Minerva will support modern MCP as an outbound stdio/Streamable HTTP client and as a local HTTP server. Keep explicitly selected legacy behavior for existing peers; never put a modern version label on an initialization-based or proprietary protocol. All owned MCP endpoints must become modern-compatible by E/F closeout; retaining an owned endpoint on legacy forever is not an acceptable shortcut. Non-endpoints need an evidenced applicability receipt.

Internal execution is not MCP transport: it carries typed call context and application results, not synthetic JSON-RPC requests. Preserve current plugin re-export. Arbitrary external-server aggregation remains excluded. Tasks, Apps, Skills, new Roots/Sampling/elicitation UX, OAuth product expansion, paid-service/microphone tests, and voice audio algorithm changes are excluded. Recognizing and safely rejecting unsupported MRTR is included.

Concrete choices:

* Shared protocol envelopes and definition/result preservation, with explicit adapters for older application payload consumers.
* A source-built isolated JSON Schema validator companion using jsoncons, supervised through existing SubProcess machinery. No bespoke general GDScript validator and no dependency on the optional Voice Python runtime.
* Minimal core subscription handling in the initial host profile: `tools.listChanged=false`, immediate-stale private catalog hints, refresh on actual discovery use. Valid inbound subscriptions/listen receives an empty acknowledged filter followed by graceful completion; no background push. Outbound clients initially do not open subscriptions. Local plugin-manager events still refresh internal catalogs.
* Proprietary plugin callbacks move to a separately authenticated local control channel. They are not core MRTR input requests. D1 must independently review the concrete channel implementation before the pilot.
* Embedded `window.minerva.call` moves behind the existing native webview IPC seam while preserving its JavaScript API. Do not allow arbitrary `Origin: null` or wildcard origins to keep old HTTP fetches working.

## 4. Profiles and compatibility

Current outbound constant is 2025-06-18. Current HTTP server advertises 2025-06-18, 2025-03-26, 2024-11-05. These are compatibility targets, not proof of complete compliance: the current 2024-11-05 label does not establish an implemented legacy HTTP+SSE transport. A/B/C tests must classify exact supported behavior. Preserve working initialized JSON/stdio paths; document legacy HTTP+SSE as unavailable unless separately evidenced. Do not advertise 2025-11-25 merely because it is the previous revision.

Modern stdio probes `server/discover` with required request metadata. Recognized modern protocol errors keep the peer modern; a non-modern error or bounded probe timeout falls back to initialization. Bound probing within the existing connection startup budget, retain new request IDs, and ignore late probe replies. Cache era per process generation. Legacy initialization validates returned version and sends initialized notification only in the legacy lane.

HTTP uses a harmless discovery request before any mutating call. Inspect JSON-RPC error bodies before fallback: unsupported-version, missing-capability, and header-mismatch errors are modern responses, not reasons to downgrade. Cache era by configured endpoint/origin and authorization context, invalidate on configuration/connection changes. No empty initialize response is sufficient evidence of a valid negotiated legacy session. Keep legacy session handling isolated from modern requests.

Modern server accepts each request independently from its metadata. No initialize requirement, protocol session ID, GET event stream, or DELETE session semantics in this lane. Legacy initialize/session behavior remains isolated. HTTP aliases may remain, with identical validation/policy. Legacy metadata absence must never bypass Origin or payload checks.

### Minimal inbound subscriptions and public dispatch admission

The pinned `basic/patterns/subscriptions.mdx` requires the acknowledgment first and defines graceful server closure (lines54–62,85–89,128–154). For valid inbound `subscriptions/listen`, HTTP responds with request-scoped SSE containing exactly these protocol messages, then closes gracefully; stdio emits the same messages on its channel. For an example request ID `1`:

```json
{"jsonrpc":"2.0","method":"notifications/subscriptions/acknowledged","params":{"_meta":{"io.modelcontextprotocol/subscriptionId":1},"notifications":{}}}
{"jsonrpc":"2.0","id":1,"result":{"resultType":"complete","_meta":{"io.modelcontextprotocol/subscriptionId":1}}}
```

`subscriptionId` is the exact original request ID, including its type, not a new session token. Each HTTP message is its own SSE `data:` event. Validate metadata/filter before acknowledgment; cancellation before completion stops further output. Empty acknowledgment honestly declines all requested notification types. No notification pump, resource API or outbound listener is introduced. Apply this core behavior to owned modern servers in D/E as well as C1. Test message order, ID/type preservation, empty filter and graceful completion, not method-not-found.

The pinned tools specification explicitly requires invocation rate limiting (`server/tools.mdx:789–795`). C1 owns a shared pre-dispatch public HTTP admission gate for both protocol eras: bounded global in-flight calls and a finite token-bucket rate/burst, applied before native/plugin execution. Initial reviewable defaults: 16 concurrent calls, 20 starts/second, burst40, no hidden execution queue; excess returns HTTP429 with Retry-After and a documented application error (not an invented reserved MCP error). Each terminal/cancel path releases admission exactly once. Caller-controlled agent_id/clientInfo/session IDs cannot bypass the global limit. More granular authenticated-principal limits may supplement it; do not claim labels authenticate a caller. C4 verifies rejection cannot execute a tool and that subsequent permitted traffic recovers. B2 surfaces overload without automatically replaying mutations. These explicit budgets may be adjusted using reviewed local workload evidence; the gate itself is mandatory.

## 6. Internal execution and result boundary

A2 introduces an explicit per-call context: origin (internal chat/external HTTP/plugin callback/panel), caller chat ID, external caller label, plugin identity when applicable, correlation token, deadline/cancellation owner. Display identity is not authenticated identity. Context is passed through nested dispatch rather than stored in `_current_caller_chat_id`/`_current_agent_id` across awaits. Those mutable fields currently permit overlapping calls to see another caller's state. Limit context-aware module plumbing to actual consumers (`MCPAgentTools` and `MCPSkillTools`, including nested agent `call_tool` paths); an optional context-aware dispatch adapter avoids changing every unrelated module signature.

Keep two representations: lossless protocol result/definition and explicit application payload. The protocol representation retains content arrays, structuredContent of any JSON type, isError, _meta, resultType and method-specific fields. Existing legacy plugin JSON-text unwrapping becomes an explicit application adapter, not the shared wire normalizer. Browser/voice/panel callers get their established application payload through that adapter. HTTP re-export uses the lossless representation when available; native application errors become MCP tool errors with isError, not successful text containing an error dictionary. RPC validation/unknown-method or unknown-tool errors remain distinct from invalid tool arguments and tool execution errors; do not flatten these into one application success/error dictionary at the wire boundary.

MCPManager external coercion remains an internal convenience before validation, not a public server mutation of raw wire arguments. Preserve policy checks and capability grants independently. Propagate deadlines through forwarding; prompt-tool LRU/token budgets are not request deadlines. Registry identity includes server ownership; do not allow a stale connection to unregister a replacement or silently resolve a colliding external tool to another server. This requires an explicit collision diagnostic, not a new aggregation namespace product.

## 7. JSON Schema reuse and bounded native dependency

Choose [jsoncons](https://github.com/danielaparker/jsoncons), release v1.9.0, commit `bcb44594c50c495ee1e690602cdd71455942ad0e`. Upstream documents Draft 2020-12 support and a header-only C++ implementation under the Boost Software License; retain all included dependency notices. A3 pins source archive hash and builds from source using the existing cross-platform C++/SCons toolchain. No checked-in executable and no Voice/Python dependency.

Expose a narrow JSON-lines companion contract: validate schema against declared/default meta-schema, compile a schema into a process-local handle, validate an instance, release handle. Godot supervises one helper through SubProcess; finite queue, request IDs, first-terminal-result ownership and restart on deadline/process failure. Existing SubProcess.write_data is blocking on Unix/Windows: large writes must use an interruptible/nonblocking path or supervised off-thread sends, never a main-thread blocking write followed by a Godot timer. Bound native output queues as well as input queues. Restart invalidates all compiled handles by process generation; retain original schema bytes for explicit recompilation. A3 builds a standalone C++17 Program without inheriting terminal/Godot/minerva-vt linkage, and acquires the verified source archive SHA plus complete offline 2020-12 vocabulary/meta-schema pins before build approval. Keep this API independent of MCP. An untrusted schema/regex must not hang the UI or an unkillable main-process native call.

Only 2020-12 is promised initially; unsupported explicit dialect is a clear error. Use bundled meta-schemas and an in-memory URI registry; resolve local references, anchors and dynamic references through the library. No default network or filesystem resolver; unresolved external references reject the schema, never become permissive. Validate schema syntax itself, not merely an example instance. Preserve unknown extension keywords as annotations where the dialect permits them.

Initial engineering limits for A3 review: 4 MiB schema document, 32 MiB instance, depth128, 100000 schema nodes, 32 queued validations, 2-second validation/compilation deadline. These are finite resource policy, not assertions of measured performance; adjust only from reviewed representative fixtures without weakening the hard-bound requirement. A single oversize schema/tool can be rejected with a useful diagnostic while unrelated tools stay available. Existing bulk document data planes are not forced through this control validator. A3 acceptance includes exact number/boolean handling, refs/dynamic refs, composition/unevaluated keywords, invalid schema, unavailable refs, malicious-pattern deadline, queue overflow, helper loss/restart and no leaked process. Review before compilation/testing. F1 packages/signs/tests the helper on every supported platform; validator unavailability fails clearly rather than silently accepting invalid schemas.

### Numeric representation and raw JSON preservation

Godot JSON parsing commonly converts JSON numbers to floating point; it is not a lossless arbitrary-integer boundary. A3 must preserve the original UTF-8 schema/instance/result bytes into the native companion before any Variant conversion, and preserve raw protocol data for forwarding. Schema validity and instance validation operate on those raw values, not on a Godot stringify roundtrip.

For native application dispatch requiring a Godot Dictionary, the adapter must reject unsupported numeric representations before execution. The initial supported integer domain is the safe integer interval `[-9007199254740991,9007199254740991]`; reject larger integer values rather than rounding them. For non-integer JSON numbers, the native helper compares the original numeric value with the value obtained after the proposed Godot parse/serialization conversion; a changed value or non-finite conversion is an explicit unsupported-representation error. Comparison uses the helper's raw numeric representation, not another double conversion. Keep string IDs when generating requests. Unsupported inbound numeric IDs must not be rounded to a different response ID; retain their raw token for a protocol rejection, or reject malformed/unrepresentable input without claiming a successful correlated dispatch.

Canonical decimals that survive this comparison remain supported. The initial
helper limits `multipleOf` to positive safe-range integral divisors, and the pinned
jsoncons source is patched to use an exact remainder check for that subset.
Non-integral divisors fail schema compilation with `unsupported_number`. This
is a declared numeric capability limit, rather than permissive fallback or a
claim of unrestricted Draft 2020-12 decimal arithmetic.

Never advertise lossless arbitrary JSON forwarding if an intermediate Dictionary has already discarded precision. The same rule applies to definitions, structuredContent, incoming arguments, panel/internal adapters, and re-export. If raw-preserving forwarding cannot be implemented at a given seam, reject the unsupported representation explicitly rather than silently changing it. A3/B/C acceptance includes safe-range boundary integers, values immediately outside it, very large exponents, fractional roundtrip changes, and unchanged raw schema/structured-result forwarding. This is a required correctness gate, not optional future numeric cleanup.

## 8. Plugin control migration contract

D1 uses a distinct host-owned loopback TCP control listener, with per-process unguessable credential, protocol version and process generation. Pass endpoint/credential only through the owned child launch environment; do not print it or place it in general MCP discovery. Authenticate before accepting any callback. Bind localhost only, bound pre-auth timeout/bytes, one connection per live plugin generation, revoke on stop/reload. Use length-prefixed UTF-8 JSON frames with the existing control payload ceiling (64 KiB); preserve separate bulk/document/audio routes.

The control channel carries existing minerva/capability, panel/state/event/host.notify semantics in a documented Minerva envelope, not JSON-RPC messages on modern MCP stdout. Each callback identifies a host-minted parent-call context token when it is part of tool execution; do not trust a supplied chat/plugin ID as authority. Independent plugin lifecycle events use a process-scoped identity, not another request's mutable context. Correlate responses, enforce grant checks, deadlines and cancellation, and reject stale generations. Capability dispatch remains in CapabilityBroker; do not duplicate tool implementation.

Control provisioning is host-local application setup, not a claim that arbitrary MCP clients understand Minerva IPC. A modern owned server with no control peer may still expose independent tools; a tool requiring host control returns an explicit unavailable/tool error. Third-party hosts can use ordinary MCP tools without receiving proprietary server requests. Old Minerva/old plugin pairs retain the legacy callback lane. Never use both lanes for the same live plugin generation. D1 decides exact framing and bootstrap fields with an independent cold review; A1 chooses the separate-channel architecture, not every field spelling.

D2 first proves the protocol with small Python fixtures/notes_helper and a real obs_controller integration, then E migrates groups by actual source reuse. Callback-heavy CAD/PCB follow proven lifecycle behavior. Voice preserves configure/start readiness ordering, stop latency, packaged immutable runtime checks, and its dedicated application's result adapter. No audio bytes move onto MCP or control IPC.

## HTTP client implementation boundary

The client uses one Godot HTTPClient per active POST, with at most 32 admitted requests and no hidden wait queue. JSON bodies and individual SSE events are limited to 32 MiB; SSE response traffic is limited to 64 MiB and 4096 events. Body reads use 64 KiB chunks. Response headers are checked after the engine parses them (8 KiB per field, 64 KiB aggregate). Godot's HTTPClient owns header and chunk-trailer parsing and currently exposes no preallocation or per-poll intake bound there. These are application-layer limits, not a claim of bounded engine header/trailer allocation or poll duration; engine hardening remains separate work.

Modern discovery is the only automatic compatibility probe. Recognized modern protocol errors retain their HTTP status and RPC error payload; tool calls are never automatically replayed, including after header correction errors. Callers can deliberately refresh the catalog and retry a rejected call. Legacy initialization and session headers are isolated from the modern profile; no GET stream, automatic redirects, Last-Event-ID replay, or modern session DELETE is introduced. HTTP cancellation closes the owned socket and settles the local request; an interrupted submitted call reports unknown outcome rather than claiming remote execution was undone.
